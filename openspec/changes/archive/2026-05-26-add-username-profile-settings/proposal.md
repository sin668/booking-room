## Why

当前小程序缺少与 `prototype/settings.html` 对齐的“设置/个人资料”页面，用户无法在移动端集中查看和维护昵称、手机号等资料，也缺少可编辑且唯一的用户名作为稳定账号标识。

注册流程也需要为新用户自动生成用户友好的唯一用户名，避免 app 用户长期缺失 `username`，并为后续通过用户名登录、展示和账号识别打基础。

## What Changes

- 在小程序端新增“我的设置”页面，视觉和交互参考 `prototype/settings.html`：顶部导航、头像资料卡、个人资料分组、账号与安全、通知设置、通用设置、关于与退出登录。
- 在“个人资料”分组中新增“用户名”项，展示当前用户名，并支持进入编辑流程。
- 新增或扩展移动端个人资料 API，允许当前登录用户读取并更新自己的用户名、昵称、头像等资料字段。
- 注册成功时由后端为未提供用户名的新用户自动生成唯一用户名，格式为“随机英文名 + 5 位随机数”，例如 `Luna48392`。
- 后端强制校验用户名格式与唯一性；生成用户名时必须处理碰撞并重试，编辑用户名时必须拒绝重复用户名。
- 保持昵称与用户名的语义分离：昵称用于显示名称，用户名用于稳定账号标识和登录/识别。
- 回滚方案：可隐藏小程序设置入口并回滚新增页面；后端保留已生成用户名数据但关闭编辑入口，注册流程可临时恢复为仅生成昵称，数据库唯一索引变更按迁移回滚脚本执行。

## Capabilities

### New Capabilities

- `profile-settings-ui`: 小程序“我的设置/个人资料”页面、用户名展示与编辑交互。
- `user-profile-api`: 当前登录用户个人资料读取与更新 API，覆盖用户名编辑、资料字段返回和重复用户名错误处理。

### Modified Capabilities

- `user-registration`: 注册流程需要在用户未提供用户名时自动生成唯一用户名。
- `unified-user-model`: app 用户不再默认保持 `username` 为 NULL，`users.username` 的唯一性规则需要覆盖 app 与 admin 用户。
- `user-auth`: 登录/当前用户资料响应需要包含用户名，并继续支持用户名登录时的全局唯一匹配。

## Impact

- 影响模块范围：
  - `br-app`：新增或完善设置页面、个人资料编辑 UI、用户 store 字段、API client、页面路由入口。
  - `br-server`：用户模型/迁移、注册服务、认证/当前用户响应 schema、个人资料 API 路由与服务、用户名生成工具。
  - `openspec/specs`：新增移动端设置 UI 与个人资料 API 能力，修改注册、统一用户模型、用户认证能力。
- API 影响：新增或扩展当前登录用户 profile 读取/更新接口；注册响应和当前用户响应应包含 `username`。
- 数据库影响：需要确保 `users.username` 对所有非空用户名全局唯一，并为既有 app 用户制定补齐或兼容策略。
- 测试影响：需要覆盖用户名生成、碰撞重试、重复用户名拒绝、设置页展示与编辑、注册默认用户名、登录/当前用户响应字段。
