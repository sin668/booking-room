## Context

当前 br-server 已有用户端钱包 API（`/api/v1/wallet/*`），br-admin 已有预约管理、用户管理等后台模块。管理端路由遵循 `/api/v1/admin/*` 前缀模式，使用 `require_admin_permission` 做权限校验。br-admin 前端使用 Vue 3 + Ant Design Vue，管理端视图放在 `src/views/` 下。

数据库中 `wallet_transactions` 表已包含完整的交易记录（类型、金额、状态、时间等），可直接用于统计查询。

## Goals / Non-Goals

**Goals:**
- 管理员可在后台查看所有用户的交易流水，支持多维度筛选
- 提供财务统计概览（总充值、总消费、总退款、净收入、用户数）
- 支持导出交易流水为 CSV
- 复用现有管理端的权限体系和 UI 模式

**Non-Goals:**
- 不做财务对账功能
- 不做手动调整用户余额（已在用户管理中支持）
- 不做退款审批流程
- 不做财务报表导出（PDF/Excel）
- 不做实时数据推送

## Decisions

### 1. 后端路由设计

**选择**: 新增 `/api/v1/admin/wallet/*` 路由，放在独立的 `admin_wallet.py` 中

**理由**: 与现有 `admin_booking.py`、`admin_user.py` 保持一致。钱包业务独立性强，不混入其他路由文件。

### 2. 统计数据实现方式

**选择**: 在 `wallet_service.py` 中新增管理端统计方法，使用 SQL 聚合查询

**理由**: `wallet_transactions` 表数据量可控（非海量），直接 SQL 聚合即可满足需求，无需引入额外的数据仓库或缓存机制。查询频率低，不会对主库造成压力。

### 3. CSV 导出

**选择**: 服务端生成 CSV 文件，通过 StreamingResponse 返回

**理由**: 与筛选条件保持一致（前端传什么筛选参数，导出就是什么数据）。前端无需处理大数据量转换。使用标准库 `csv` + `io.StringIO` 即可，无需额外依赖。

### 4. 前端页面结构

**选择**: 在 br-admin 新增 `wallet` 视图目录，包含流水列表和统计概览两个页面

**理由**: 钱包是独立的业务模块，与预约、用户管理平级。统计概览放在列表页顶部作为卡片展示，保持信息密度。

### 5. 权限标识

**选择**: 使用 `wallet:view` 和 `wallet:export` 两个权限标识

**理由**: 遵循现有的细粒度权限模式（如 `booking:view`、`booking:cancel`）。查看和导出是两个不同的操作级别。

## Risks / Trade-offs

- **[数据量增长]** → 初期直接查询足够，若未来交易量大幅增长，可引入定时预计算统计表
- **[CSV 导出大数据量]** → 限制单次导出最多 10000 条记录，超出时提示用户缩小筛选范围
- **[统计实时性]** → 统计数据为实时查询，适合当前规模，若需更高性能可后续加缓存
